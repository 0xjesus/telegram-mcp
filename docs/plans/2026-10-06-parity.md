# Telegram parity implementation plan

Goal: publish Telegram MCP on main and provide the same supported attachment processing and cross-platform messaging capabilities as the WhatsApp fork.

Architecture: reuse the audited attachment extraction and OpenAI modules, with a Telegram-specific durable adapter. Keep a single Telegram session in the daemon; workers download through MCP. Extend the shared history source to index Telegram attachment analysis. Add native Telegram tools in a separate module.

Constraints: no real outbound test messages or account/group/privacy mutations. Respect existing consent, freshness, FloodWait, deletion and media-replacement checks. Bound queue scans, batch sizes, downloaded files, subprocess memory/time, retries and cache lifetime. Share the existing OpenAI budget ledger in production, keeping the combined attachment budget at US$10/month. Preserve all explicit group overrides. Never commit secrets, sessions, databases or user message content. User explicitly authorizes main, public repository, commits, deployment, and requests no additional questions.

1. Add Telegram attachment adapter and tests, reusing extraction/cloud modules with attribution; support image/sticker/PDF/Office/text extraction, cloud resume and budgets; integrate source indexing and validation against current message identity and consent.
2. Add equivalent supported group, poll, contact-card and privacy tools; serialize/rate-limit mutations, expose precise native restrictions and validate schemas; synthetic tests only.
3. Close media/history gaps: audio/video transcription and video previews, received reactions, no deleted-message resurrection. Test these independently.
4. Add installation dependencies, service examples, documentation and CI with synthetic tests. Audit all public history for secrets.
5. Review diff, resolve findings, run affected/full suites, commit and push main in both repositories where changed. Deploy to existing host without new Telegram sessions, confirm tool catalog, attachment index integration and service health. Report real platform limitations.
